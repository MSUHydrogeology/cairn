**Author**: Claude Sonnet 5.5 (Strategy)
**Source proposal**: [dev/proposals/archive/2026-10-26-claude-upgrade-removes-untouched-retired-files.md](../proposals/archive/2026-10-26-claude-upgrade-removes-untouched-retired-files.md)

**Opened**: 2026-10-26
**In brief**: A new `upgrade` step deletes retired Cairn files that a project never edited and clears the records of ones it already deleted, so tidying up no longer breaks `--finalize` or the integrity check.

The Internal Security Review is a separate pass from the ordinary plan review, and the ordinary pass never clears it. This is the first engine code that deletes a file in a project.

## Source proposal

Accepted 2026-10-26 as revised, with all five defaults. **Revision 2 is the contract** and supersedes Revision 1; it adopts the Security Review's conditions SR1 to SR5 and recommendations R1, R2. One new action, `upgrade --remove-retired`, and one engine list of 30 retired files with the SHA-256 digests (fingerprints) of every version Cairn shipped. A copy is removed only if its bytes match a digest and git's last commit holds the same bytes. Anything else is kept and named. `--plan`, the step and `--finalize` share one classifier.

**C2.**
* `_committed_copy_matches(project_root, rel_path, data)` (`upgrade.py`) is a function of its own, importable by the later row. It runs `git -C <project> -c core.fsmonitor=false -c core.hooksPath=<null device> -c core.useReplaceRefs=false cat-file blob HEAD:./<rel_path>`, no input, a timeout, and passes only on exit 0 and exactly `data`. It reads at most `len(data) + 1` bytes of git's output and kills git at a fixed timeout (a module constant, `_GIT_TIMEOUT_SECONDS`), so a hang or an endless stream keeps the file: `test_a_git_that_does_not_finish_or_prints_too_much_keeps_the_file` puts a stand-in `git` first on `PATH` that sleeps, then prints exactly `data`, with the constant patched to 0.5 s (no environment variable), and one that prints without end; mutants: no timeout (the sleeper's late answer passes); an unbounded read.
* Its environment has every `GIT_*` variable removed and `GIT_NO_LAZY_FETCH=1`, `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0` added. `test_committed_copy_matches_runs_git_with_fixed_overrides_and_environment` captures argv and environment, and `test_committed_copy_matches_ignores_a_replace_ref` (a real repository whose replace ref swaps the file's blob keeps the file). Mutants: call `git status`; drop `GIT_NO_LAZY_FETCH`; drop `core.useReplaceRefs=false`.
* The function itself reads `git --version` once per process, so every caller gets the floor: `test_a_git_older_than_2_45_or_unreadable_keeps_the_file_and_runs_no_cat_file` (below 2.45.0 or unreadable fails the check; control: 2.45.0 passes). `git --version` runs with the same cleaned environment and the same byte cap as the `cat-file` call, and parses vendor suffixes: `2.54.0 (Apple Git-157)` (this machine's `/usr/bin/git`, measured) passes and `2.44.9 (Apple Git-1)` fails, one node each.
