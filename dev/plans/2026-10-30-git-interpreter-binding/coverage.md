The existing shell-script interpreter fixtures skip Windows and cannot prove the new authority boundary. Add `bootstrap/tests/test_git_interpreter_binding_portable.py` (proposed) with real subprocess entry points, using the running Python and portable markers. Its `test_legacy_marker_control_and_mutant` copies the candidate into disposable directories, runs an unmutated control, then redirects the resolver deliberately to the old binding and runs the same entry point; the marker assertion must pass for the control and fail for the mutant. Run `python -m pytest bootstrap/tests/test_git_interpreter_binding_portable.py` under canonical Python on the final commit; record control and mutant separately. Mutations never touch the shared tree.

The same file must exercise installer and both session copies for ordinary `.git` directories and regular Git pointers in linked, separate-directory and submodule layouts; two worktrees with distinct bindings; non-repository and nested targets with an unchanged ancestor binding; scrubbed hostile Git variables and genuine discovery errors; absent versus dangling, unreadable and wrong-type binding state; filesystem links at the `.git` pointer and each binding-path component; unsafe destination under force and non-force with an external sentinel unchanged; and refusal before a marker executable launches. Check valid, malformed, stale and tracked executable cases and explicit rebinding. Run the same command on native Windows and record its interpreter and results, including junction/reparse points at the pointer and binding-path components. If platform privileges or unsupported link types prevent a required case, it remains open rather than becoming a skip accepted as evidence.
