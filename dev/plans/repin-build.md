## Source proposal

Accepted 2026-10-26 as revised. **Revision 3 is the contract** (it supersedes Revisions 1 and 2 for reading). One script, `scripts/repin.py`, with three verbs: `status` (reads, writes nothing), `package` (computes the AST pin's transaction and prints its digest) and `ceremony` (the whole sequence, 11 steps). The Decision's answers bind: **one key** signs releases and the anchor (recorded departure); the same-user limit for signing is accepted as stated; and **the script does not commit the AST pin**. After the Maintainer's yes it writes the pin, checks what it wrote, prints the `git commit <paths>` line and stops. This differs from Revision 3's default, so no chunk contains a commit step for the AST pin.

## Sequence

Tests are named for the property (`test_a_loaded_key_refuses_before_stage_one`), never for a finding or chunk. A comment or docstring explains the code, not the review that asked for it. **R2: the AST transaction and the apply step.**
* **No `repin` path writes `gate_manifest.json`.** The output set is hard-coded (the AST baseline, `scaffold_ast_known_new.json`, the lockfile if R5 is built). A transaction naming `gate_manifest.json` or any other path refuses, and the manifest's blob id is unchanged (control: the baseline alone passes).
* The transaction is one JSON file bound by its SHA-256: head and anchor ids, each output's preimage blob id and SHA-256, the influences outside the tracked tree (interpreter, git, blob id of `encode_display`), the full new bytes and the rendered summary. Two trees that differ only in a kept record give different digests; an edited output byte refuses.
* The apply step reads the transaction once into memory and **renders Summary 1 itself from the bytes it will write**: a key-by-key comparison of the file on disk with the output, never stored text and never `_classify` (`test_every_key_the_write_changes_is_on_screen_before_the_question`; control: drop one row from the render and the test fails). Only the exact word `yes` from a terminal writes; `Yes`, `y`, an empty line, end of input and a pipe are no. `ceremony` step 5 writes only the transaction it packaged in the same process, never one found on disk, and re-resolves `HEAD` immediately before the first `os.replace`: if it differs from the transaction's head id it refuses and writes nothing (`test_head_moving_between_package_and_write_refuses`).
* Safe writes: `mkstemp` in the target's folder; refuse a symlinked target or parent, an untracked or non-regular target, a transaction file that is a symlink, not the user's own or writable by others; `O_NOFOLLOW`; compare-and-swap immediately before `os.replace`; with two outputs, both temporaries written and checked before either is replaced; after a partial failure print what was replaced and the exact `git restore --source=<head-id> -- <path>` line, exit non-zero, restore nothing (tests: changed preimage; symlinked target; symlinked parent; outside path; a planted `<name>.tmp` link; a transaction file that is a symlink, not the user's own, or writable by others, one test each). `repin` writes its own containment rule and says in a comment why it does not import `_guard.py`.
* **Preconditions**, one function shared by `ceremony` step 2 and the apply step, each with a test and a control: stdin or stdout not a terminal (`test_a_pipe_on_stdin_or_stdout_refuses`); `HEAD` not on a branch (`test_a_detached_head_refuses`); a dirty tracked file (`test_a_dirty_tracked_file_refuses_before_any_write`; the post-write check below is exact only because of it; control: a clean tree passes); any `assume-unchanged` or `skip-worktree` entry (a lowercase tag or `S` in `git ls-files -v -z`; `test_an_index_bit_that_hides_changes_refuses`; control: no bits passes; measured: with either bit an edited file printed nothing in `git status`); interpreter minor not the pinned one (`test_a_different_interpreter_minor_refuses`). Until R4 builds `ceremony`, R2's tests call `apply_pin()` directly; R4 repeats the path through the command line.
* **No commit.** After the write the script checks, with sterile git, hooks off, `--no-ext-diff` and `core.fsmonitor=false`, that only the named paths differ from `HEAD`, and that each named file hashed with `git hash-object --no-filters` (not `git status`, which a same-size, same-mtime edit can fool) equals the blob of the bytes shown; on a mismatch it refuses and prints the undo line without running it. It then writes the stop record (head id, paths, blob ids; R4's re-run check reads it) beside the transaction in `--ceremony-dir`, prints the `git commit <paths>` line, the digests to put in the commit body, and "commit these paths, then run ceremony again", and **stops** (`test_the_apply_step_makes_no_commit_and_stops`: `HEAD` unchanged; control: the check passes on a clean write). An AST pin with `MISSING` or `DUPLICATE` symbols, or a pin that adds or drops a baseline key, refuses (it is a review item). When the known-new file is an output, the screen says it changes a frozen gate file and owes a re-anchor.

* *One prompt, and the passphrase is the only control.* On a pseudo-terminal with the key unloaded, a scratch ceremony counts exactly one passphrase prompt (control: socket left in, zero prompts); no terminal, no signature. The script never reads, stores or passes the passphrase. The grep of the signing path for stdin, `getpass` and environment reads is a **tripwire only**, and `test_a_planted_getpass_makes_the_signing_path_grep_fail` plants `getpass.getpass()` in a copy of the function. The behavioural test is `test_the_typed_passphrase_appears_nowhere_the_script_writes`: the test's own throwaway passphrase, typed on the pseudo-terminal, is in no argv, no environment, no file and none of the script's output. The instrument: the harness starts `python -I` with a small wrapper that installs `sys.addaudithook` and runs `scripts/repin.py` with `runpy` (already isolated, so no re-exec drops the hook, and `repin` needs no seam). The hook appends to a log file each `subprocess.Popen` (argv and env slot), `os.exec*`, `os.posix_spawn`, `os.forkpty` and write-mode `open`; a file, because a forked child's memory is lost. I measured that `Popen` events carry argv and an env slot, `open` events carry the mode and `os.forkpty` shows no argv; I did not measure a pty child's own exec event.
