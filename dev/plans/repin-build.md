**Author**: Claude (Strategy)
**Source proposal**: [dev/proposals/archive/2026-10-26-claude-repin-build.md](../proposals/archive/2026-10-26-claude-repin-build.md)

**In brief**: Build one tested script that runs the Maintainer's checksum re-pins and the signed re-anchor, so he compares two digests, answers two summaries and types one passphrase instead of pasting commands an agent wrote.

The Internal Security Review is a separate pass from the ordinary plan review. It checks that the proposal's Security Review findings (SR-1 to SR-7 and SR2-1 to SR2-6) are carried into this plan, by the table under Acceptance criteria. The ordinary pass does not clear it. Four points are **marked for it** because the plan author decided them without the Maintainer: the SR2-6 (a) departure and the re-run check added to it, the `tools/session.py` exemption in R1, the 11-file list, and R6b's order after M2.

## Source proposal

Accepted 2026-10-26 as revised. **Revision 3 is the contract** (it supersedes Revisions 1 and 2 for reading). One script, `scripts/repin.py`, with three verbs: `status` (reads, writes nothing), `package` (computes the AST pin's transaction and prints its digest) and `ceremony` (the whole sequence, 11 steps). The Decision's answers bind: **one key** signs releases and the anchor (recorded departure); the same-user limit for signing is accepted as stated; and **the script does not commit the AST pin**. After the Maintainer's yes it writes the pin, checks what it wrote, prints the `git commit <paths>` line and stops. This differs from Revision 3's default, so no chunk contains a commit step for the AST pin.

## Sequence

How to work: directly on `0.5-dev` in the shared checkout, no branch or worktree for writing. `python tools/intent.py claim --files <paths> --action "<what>"` before editing; commit by explicit path. **An agent chunk never signs except with a throwaway key in a scratch folder (R4's tests), never reads `~/.ssh` or the real anchor, never runs `repin ceremony`, `--first-run` or the apply step against the working repository (`status` and `package` are read-only and allowed), never pushes, never runs a re-anchor, and never types the Maintainer's passphrase (the tests type their own throwaway one).**

## Acceptance criteria

Each criterion names its test or command. Each refusal test has a control that passes when the condition is fine. Tests are named for the property (`test_a_loaded_key_refuses_before_stage_one`), never for a finding or chunk. A comment or docstring explains the code, not the review that asked for it. Test paths: `bootstrap/tests/test_repin.py` (R1 to R3, R5) and `bootstrap/tests/test_repin_ceremony.py` (R4). Proposed paths are declared at the end of this section.

**R1: core and AST `status`.**
* The fixed six-step reading order runs before anything is shown: `HEAD` and the anchor resolved once; the anchored manifest read as data; `HEAD` extracted from the raw object graph with `ls-tree -r -z --full-tree` and `cat-file`, **never `git archive`** (it obeys a tracked `.gitattributes`; `test_the_extraction_ignores_gitattributes`: a scratch repository with `export-ignore` on an engine file and `export-subst` on a listed file still extracts both byte for byte; control: no attributes file); then **these 11 files** byte-compared with their anchored `frozen_files` entries **before any import**: `bootstrap/tests/__init__.py`, `_ast_attest.py`, `scripts/reanchor_ceremony.py`, `scripts/repin.py`, and the seven modules `_gate_preflight` loads, which are the Python members of its declared closure (`_gate_preflight`, `_gate_manifest`, `_gate_reanchor`, `_gate_transition`, `_oracle_activation`, `_oracle`, `_oracle_trust`; from the imports at `bootstrap/tests/_gate_preflight.py:49-53`, `_gate_reanchor.py:48-58`, `_oracle.py:77`). The `repin` process imports `_gate_manifest`, `_gate_preflight` (and through it the other five) and `reanchor_ceremony`; the AST child imports `_ast_attest`. Every member is frozen, so each has an anchored entry. `test_each_imported_file_is_byte_compared_with_the_anchor_before_import`: one mutated file per member, each carrying a marker that writes a file if run, refuses with the marker file absent (control: anchored bytes pass). The AST work runs in a child under `python -I -X pycache_prefix=<fresh folder>` (`test_the_ast_child_runs_isolated_with_a_fresh_pycache_prefix`, reading the child's `sys.flags` and `sys.pycache_prefix`). After import, a loaded local module outside the list refuses (`test_a_loaded_local_module_outside_the_list_refuses`: in a scratch bed whose anchor pins its own bytes, a planted module imported by a listed module is seen loaded and refuses; control: the same bed without the import passes).
* **`encode_display` is the one allowed extra.** It comes from `tools/session.py` (byte-identical to `templates/skills/_lib/session.py`, which defines it). That file is neither frozen nor in the closure, so the anchor holds no entry for it: it is loaded from the extraction of `HEAD`, the blobs of the two copies must be identical, its blob id goes in the transaction, and the post-import check names it as the only extra. It is a display aid, not an authority: digests and ids print as plain hex, never through it. **Marked for the Security Review.**
* A tracked `.pyc` under an import root refuses. A candidate commit changing `_ast_attest.py` refuses with no write. A closure-member blob change refuses an AST pin (control: an unrelated change passes).
* An untracked engine module in the working tree is absent from the output; once committed it appears. `HEAD` moving refuses.
* Provenance lines read "the message names `<stem>` (status `<Status>`)" or "the message names no plan or proposal", and no refusal depends on them. A commit subject with ESC and CR prints escaped through `encode_display` (control: an ordinary subject is unchanged). Git output is read as bytes.
* Zero-member sets refuse. `status` writes nothing: a before-and-after tree comparison in the test.
* Standing: Bandit scan (`bootstrap/tests/test_security_lint.py`) clean with the `ALLOWLIST` unchanged; `python bootstrap/tests/_gate_manifest.py verify --no-collect` run before the chunk and after it: the `FROZEN-*` lines differ by exactly the `FROZEN-NEW` lines for the new files (the tree already carries owed `FROZEN-MODIFIED` rows, so "lists only" would be false).

**R2: the AST transaction and the apply step.**
* **No `repin` path writes `gate_manifest.json`.** The output set is hard-coded (the AST baseline, `scaffold_ast_known_new.json`, the lockfile if R5 is built). A transaction naming `gate_manifest.json` or any other path refuses, and the manifest's blob id is unchanged (control: the baseline alone passes).
* The transaction is one JSON file bound by its SHA-256: head and anchor ids, each output's preimage blob id and SHA-256, the influences outside the tracked tree (interpreter, git, blob id of `encode_display`), the full new bytes and the rendered summary. Two trees that differ only in a kept record give different digests; an edited output byte refuses.
* The apply step reads the transaction once into memory and **renders Summary 1 itself from the bytes it will write**: a key-by-key comparison of the file on disk with the output, never stored text and never `_classify` (`test_every_key_the_write_changes_is_on_screen_before_the_question`; control: drop one row from the render and the test fails). Only the exact word `yes` from a terminal writes; `Yes`, `y`, an empty line, end of input and a pipe are no.
* Safe writes: `mkstemp` in the target's folder; refuse a symlinked target or parent, an untracked or non-regular target, a transaction file that is a symlink, not the user's own or writable by others; `O_NOFOLLOW`; compare-and-swap immediately before `os.replace`; with two outputs, both temporaries written and checked before either is replaced; after a partial failure print what was replaced and the exact `git restore --source=<head-id> -- <path>` line, exit non-zero, restore nothing (tests: changed preimage; symlinked target; symlinked parent; outside path; a planted `<name>.tmp` link; a transaction file that is a symlink, not the user's own, or writable by others, one test each). `repin` writes its own containment rule and says in a comment why it does not import `_guard.py`.
* **Preconditions**, one function shared by `ceremony` step 2 and the apply step, each with a test and a control: stdin or stdout not a terminal (`test_a_pipe_on_stdin_or_stdout_refuses`); `HEAD` not on a branch (`test_a_detached_head_refuses`); a dirty tracked file (`test_a_dirty_tracked_file_refuses_before_any_write`; the post-write check below is exact only because of it; control: a clean tree passes); interpreter minor not the pinned one (`test_a_different_interpreter_minor_refuses`). Until R4 builds `ceremony`, R2's tests call `apply_pin()` directly; R4 repeats the path through the command line.
* **No commit.** After the write the script checks, with sterile git, hooks off, `--no-ext-diff` and `core.fsmonitor=false`, that only the named paths differ from `HEAD`, and that each named file hashed with `git hash-object --no-filters` (not `git status`, which a same-size, same-mtime edit can fool) equals the blob of the bytes shown; on a mismatch it refuses and prints the undo line without running it. It then writes a record (head id, paths, blob ids) beside the transaction in `--ceremony-dir`, prints the `git commit <paths>` line, the digests to put in the commit body, and "commit these paths, then run ceremony again", and **stops** (`test_the_apply_step_makes_no_commit_and_stops`: `HEAD` unchanged; control: the check passes on a clean write). An AST pin with `MISSING` or `DUPLICATE` symbols, or a pin that adds or drops a baseline key, refuses (it is a review item). When the known-new file is an output, the screen says it changes a frozen gate file and owes a re-anchor.
* `package` at a commit and again in a detached checkout gives one digest.
* Standing: `test_ast_attest.py` (owns the baseline), `test_security_lint.py`, redundancy gate.

**R3: manifest `status`.** After the reading order it calls `verify(..., do_collect=False)` on the extraction and lists `FROZEN-MODIFIED`, `FROZEN-MISSING` and new frozen files, and says it does not check collection (`test_manifest_status_lists_drift_and_says_it_skips_collection`). `status --dropped-from <file>` prints first the dropped nodes whose test file still exists (`test_dropped_nodes_with_a_surviving_file_print_first`). Standing: `test_gate_manifest.py`.

An edited `scripts/reanchor_ceremony.py` (or any listed file) refuses `ceremony` and the message names the by-hand runbook (`test_an_edited_listed_file_refuses_and_names_the_by_hand_runbook`; control: anchored bytes pass), because the only way past it is the ceremony that anchors the new bytes. `--first-run` means "the anchored entry is absent or different": it refuses when the entry equals the running file, refuses an owed AST pin, and refuses on any output from the reviewed-commit diff over all three paths (`scripts/repin.py`, `test_repin.py`, `test_repin_ceremony.py`; `test_a_change_to_the_ceremony_tests_alone_refuses_first_run`; control: no change passes).
